# Repository Tour: Where To Find What, And What It Means

This repository preserves a long research trace. Folder names tell you **where
an artifact belongs**, but not automatically how strong its conclusion is. Read
the artifact's status, source contract, and current supersession notes before
using it.

V55 adds no scientific claim. This tour explains the existing storage and
evidence boundaries.

## The 90-Second Route

```text
README.md
  -> docs/onboarding/README.md          public orientation
  -> meta/CURRENT_STATUS.md             current scientific/operational state
  -> docs/reports/FINDINGS_REPORT_V37.md scored authoritative synthesis
  -> docs/history/V54_RUN_SUMMARY.md    latest scientific run summary
  -> meta/V55_QUEUE.md                  current communication work state
```

For a single result, follow its bracketed claim ID through
[`ONBOARDING_CLAIM_SOURCES_V55.tsv`](ONBOARDING_CLAIM_SOURCES_V55.tsv) to the
controlling artifact. Do not cite onboarding prose when the source artifact is
available.

## The Map By Epistemic Role

| path | what belongs there | how to treat it |
|---|---|---|
| `docs/findings/` | Bounded finding and kill records. | Read the scope and status; “finding” does not automatically mean externally validated or actionable. |
| `docs/reports/` | Cross-project syntheses such as the V37 scored findings and V52 therapeutic path. | Best high-level scientific account; later correction records may narrow earlier wording. |
| `docs/workups/` | Detailed genetics, treatment-response, and other domain analyses. | Inspect methods, caveats, and exact evidence behind a report statement. |
| `docs/history/` | Versioned slates, run summaries, frontier records, and decision history. | Essential audit trail; earlier enthusiasm may be superseded by a later demotion or null. |
| `docs/locked_rules/` | Rules and methods frozen before a later test. | Immutable test objects. Do not edit to improve a result after outcomes are visible. |
| `docs/validation/` | Preregistrations, interpretation grids, data contracts, intake gates, runbooks, and acquisition requests. | Operational instructions for future data. Read eligibility and fail-closed conditions before touching a package. |
| `analysis/` | Machine-readable outputs and reports generated by committed scripts. | Rerunnable support for project claims or method checks; inspect each output's purpose and whether its data are real or synthetic. |
| `scripts/` | Analysis, ingestion, gate, simulation, and audit code. | Execution machinery, not evidence by itself. A script that was not run produces no result. |
| `data/` | Held public-data manifests, derived inputs, and selected raw inputs. | Restricted working material. Follow provenance/use terms and current runbooks; never treat a file's presence as permission or eligibility. |
| `knowledge/` | Internal project indexes, decisions, candidates, and tool notes. | Project-side navigation and reasoning support; authoritative scientific status still lives in source findings/reports. |
| `knowledge_external/` | Literature, public-resource, model-output, catalog, and predicted-structure context kept outside the project-evidence tree. | Context and proposal material only; never evidence for a project conclusion merely because it is recorded here. `[E02-E03]` |
| `meta/` | Current status, next actions, queues, resume state, and block accounting. | Operational truth about what is active or blocked; not a biological evidence layer. |
| `docs/onboarding/` | Plain-language explanations, visuals, collaborator puzzles, and contribution routes. | Communication derived from bounded source claims; no scientific status originates here. |

## Start With Current State, Not The Oldest File

### `meta/CURRENT_STATUS.md`

This is the first operational checkpoint. It identifies the current scientific
state, active routes, and named next actions. It is deliberately more current
than a historical hypothesis slate.

### `docs/reports/FINDINGS_REPORT_V37.md`

This is the authoritative scored synthesis across positive results, negative
relationships, kills, and methods. Scientific relevance, novelty, and evidence
strength remain separate. It says plainly that the project has no
intervention-grade target or clinically validated biomarker. `[E01]`

### `docs/history/V54_RUN_SUMMARY.md`

This is the latest completed scientific run summary. V54 established no
progression marker, mechanism, target, treatment effect, or halt strategy; it
also records the exact data design now required. That is a corpus/design
boundary, not proof that progression biology is absent. `[P01-P05]`

### `meta/V55_QUEUE.md`

This is the live V55 communication queue and time/accounting record. It reports
what onboarding work is complete or in progress. V55 does not change the V54
scientific evidence state.

## How To Audit One Scientific Claim

Suppose you encounter: “The APC/HLA-II score is the one live clinical lead.”

1. Find its claim ID, `[M01]`, in the
   [machine-readable source contract](ONBOARDING_CLAIM_SOURCES_V55.tsv).
2. Read the allowed scope and forbidden overread.
3. Open the controlling sources:
   [`FINDING_V22.md`](../findings/FINDING_V22.md) and
   [`THERAPEUTIC_PATH_V52.md`](../reports/THERAPEUTIC_PATH_V52.md).
4. Follow the locked object to
   [`LOCKED_RULE_V22.md`](../locked_rules/LOCKED_RULE_V22.md).
5. Inspect the rerunnable robustness and confounder records in
   [`ROBUSTNESS_MAP_V28.md`](../workups/treatment_response/ROBUSTNESS_MAP_V28.md)
   and
   [`CONFOUNDER_AUDIT_V32.md`](../workups/treatment_response/CONFOUNDER_AUDIT_V32.md).
6. For the next outside test, read
   [`PREREGISTRATION_V42.md`](../validation/PREREGISTRATION_V42.md) before any
   data are opened.

That chain preserves the actual status: provisional monitoring association,
small internal evidence set, immune-tone bounded, outside validation pending,
not a target or clinical tool. `[M01-M05, A01]`

## Findings, Reports, Workups, And Analysis Are Different

These layers deliberately repeat some content for different jobs:

- A **finding record** states a bounded result.
- A **workup** explains how the result was tested and where it failed.
- An **analysis directory** contains generated tables, summaries, and other
  machine outputs.
- A **report** places the result among the rest of the project.
- A **history record** preserves how confidence changed over time.

Repetition across those layers is traceability, not independent replication.
Two files derived from the same people or labels remain one evidence source.

## Locked Rules And Validation Plans

`docs/locked_rules/` contains the object being tested. `docs/validation/`
contains the data and interpretation contract around that object.

For the monitoring route, the important distinction is:

```text
LOCKED_RULE_V22.md                 feature and score that cannot be retuned
PREREGISTRATION_V42.md             ingestion, endpoint, test, and analysis budget
OUTCOME_INTERPRETATION_GRID_V42.md meaning of pass/fail/inconclusive
scripts/v42_gafson_validation_harness.py mechanical implementation
analysis/v42_harness_validation/   synthetic method checks, not MS evidence
```

Synthetic results test software, power, and failure behavior under stated
assumptions. They must never be cited as biological evidence about MS. `[A03]`

## Data: Do Not Browse First And Rationalize Later

The `data/` tree includes manifests, derived public inputs, and some raw
materials. A newcomer should begin with the relevant manifest and validation or
analysis contract, not by opening files opportunistically.

Before using any package, establish:

1. provenance and permitted use;
2. person/sample/time mapping;
3. outcome definition and timing;
4. required feature coverage;
5. source, batch, treatment, and quality metadata;
6. whether the package is development, validation, or quarantined; and
7. the committed analysis and stop rules.

Never open a reserved validation cohort outside its frozen path. Never commit
credentials, patient-identifiable data, proprietary returned packages, or large
temporary caches. The [data-needed map](DATA_THAT_WOULD_CHANGE_THE_ANSWER.md)
explains why a near-match cannot silently substitute for an eligible package.

## Outside Context Has A Separate Address

Current outside-source material belongs under `knowledge_external/`, with
source and access provenance attached. The formal policy is
[`EPISTEMIC_CLASSES.md`](../knowledge/EPISTEMIC_CLASSES.md), and the public
entry point is [`knowledge_external/INDEX.md`](../../knowledge_external/INDEX.md).

Use outside context to:

- understand established background;
- find a dataset or method;
- identify a contradiction worth testing; or
- propose a future grounding route.

Do not use it to upgrade a project result, reopen a closed lead, or bypass a
locked validation. Model-generated prose and predicted structures stay in this
context/proposal role unless a separate project analysis grounds a concrete
prediction. `[E02-E03]`

## Historical And Legacy Trees

`archive/`, `phases/`, and older `results/` paths preserve earlier execution
and outputs. They are useful for reproducibility and understanding why an idea
changed status. They are not the fastest route to the current verdict.

Likewise, older `literature/` or support material should not be treated as the
current outside-context registry. Use `knowledge_external/` for classed public
context and the current source policy.

## Secrets, Environments, And Temporary Material

- `.env` holds local credentials and is not a source artifact. Never commit its
  contents.
- `.venv*` and `environment/` support reproducible execution; dependency
  presence does not validate a result.
- Temporary downloads, model weights, caches, and large intermediate files do
  not belong in git.
- Files under `tmp/` and tracked files over 50 MB are blocked by the repository
  hygiene policy.

## Choose A Route By Contribution Type

### I have a research direction

Read [Open Problems](OPEN_PROBLEMS_FOR_COLLABORATORS.md), check the
[Failure-Mode Atlas](FAILURE_MODE_ATLAS.md), and submit through
[How To Contribute Ideas](HOW_TO_CONTRIBUTE_IDEAS.md).

### I have a dataset

Start with [Data That Would Change The Answer](DATA_THAT_WOULD_CHANGE_THE_ANSWER.md).
Supply metadata and use terms before raw values. Do not call a cohort usable
until pairing, labels, required genes, timing, and provenance are verified.

### I want to reproduce a result

Start at its claim row, read the controlling workup/finding, then locate the
named script and `analysis/` output. Record environment, command, seed, and
input manifest. Do not substitute a nearby dataset or endpoint silently.

### I want to review outside literature

Use the separate external index and preserve source/class labels. A paper can
suggest a comparison; it cannot override a rerunnable result or become one by
being summarized.

### I want to improve communication or software

Read [`CONTRIBUTING.md`](../../CONTRIBUTING.md), run the exact checks listed
there, and state whether your change affects wording, code behavior, generated
outputs, or evidence. Communication improvements must not change claim status.

## Five Repository Mistakes To Avoid

1. **Newest file equals strongest evidence.** It may be an operational queue or
   a communication artifact.
2. **More files equal replication.** Multiple outputs can derive from one
   cohort.
3. **A script equals a result.** Only a recorded run with traceable inputs and
   outputs counts.
4. **A stored outside claim equals project evidence.** Storage is not grounding.
5. **A raw package is fair to inspect.** Validation and use terms may require a
   blind, fail-closed intake path.

When uncertain, start from the current status and claim-source contract, then
walk downward to the controlling artifact and rerunnable output. That route is
slower than browsing by filename and much less likely to create a false story.
